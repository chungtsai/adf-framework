# ADF v5.5 → v5.6 升級 SOP

## 適用範圍
已用 v5.1.0～v5.5.0 完成 `adf-project-install` 導入（有 `.adf/project.yaml` 與 `.adf/migration.json`）的專案。尚未導入的 v5.0 專案，請依 [v5.0 → v5.1 SOP](5.0-to-5.1.md) 的流程，並把文中的 tag 換成 v5.6.0。

v5.6 只新增 Module 檢查工具（`adf-project-install/scripts/module-check.mjs`），Skill 數量（34 支）與流程不變。既有 Module 文件不需修改，也不撤銷任何核准狀態；不需要重跑 APPLY。

## 1. 升級前
1. 確認工作目錄乾淨，或先 commit 未提交變更。
2. 若曾手動修改已安裝的 ADF Skill，先把客製內容保存到專案外；重新安裝會覆蓋 Skill 檔案。

## 2. 更新

一行完成（自動沿用 Agent 與安裝模式、備份、比對、VERIFY，失敗自動還原）：

```bash
curl -fsSL https://raw.githubusercontent.com/chungtsai/adf-framework/main/scripts/update.sh | bash -s -- --version v5.6.0
```

Windows PowerShell：`& ([scriptblock]::Create((irm https://raw.githubusercontent.com/chungtsai/adf-framework/main/scripts/update.ps1))) -Version v5.6.0`。

正式版發布前試用測試版：把指令中的 `main` 與 `v5.6.0` 都換成 `v5.6.0-beta.1`。

或手動執行（Agent 與安裝模式沿用原本的選擇）：

```bash
npx skills add https://github.com/chungtsai/adf-framework/tree/v5.6.0 --list
npx skills add https://github.com/chungtsai/adf-framework/tree/v5.6.0 --skill '*' -a claude-code
```

檢查 `skills-lock.json`：34 支 Skill 的 `ref` 都是 `v5.6.0`（測試版為 `v5.6.0-beta.1`），`computedHash` 已更新。

## 3. 驗收

```bash
node <skill-root>/scripts/project.mjs CHECK <project>
node <skill-root>/scripts/project.mjs VERIFY <project>
node <skill-root>/scripts/module-check.mjs <project>/modules/<module-id>
```

- CHECK 沒有 blockers，VERIFY 回傳 `verified`。
- `module-check.mjs` 能執行並輸出檢查結果與覆蓋率；有錯誤或警告不影響升級，見第 4 步。
- `.adf/project.yaml` 的 `tool_version` 維持 `5.1.0`～`5.5.0` 是正常的；5.6.0 接受此設定，不需要手動修改。

## 4. （可選）試用 Module 檢查工具

挑一個 Module 執行，看看結果是否合理：

```bash
node <skill-root>/scripts/module-check.mjs modules/<module-id>
node <skill-root>/scripts/module-check.mjs modules/<module-id> --gate
```

- 工具只讀檔案，不會修改 Module。要不要依結果修正文件，由 Human 決定；修正行為仍依原本的 Skill 流程（例如另開 `CHANGE`）。
- 常見的第一次結果：
  - 範本範例列殘留，會報「引用的 ID 不存在」。
  - traceability 一列寫多個 Test，會報警告。
  - 5.5.0 之前的 Work Item 沒有 `changes`，會出現資訊訊息。
- 也可以請 Agent 執行並說明結果：

```text
請執行 node <skill-root>/scripts/module-check.mjs modules/<module-id> --gate，逐項說明錯誤、警告與結案預檢的結果，分成「文件寫法問題」與「真正的缺漏」兩類。不要修改任何文件。
```

- 誤報或看不懂的訊息，請回饋到 adf-framework 的 issue，作為正式規則的依據。

## 常見問題
- **出現 `Missing/unsupported formal npx source`**：部分 Skill 仍是舊版，重新執行第 2 步並安裝全部 34 支。
- **出現 `Installed skill differs from npx lock`**：已安裝的 Skill 被手動修改過，先把客製內容移到 `standards/` 或專案外，再重新安裝。
- **`module-check.mjs` 回傳 exit code 2**：找不到 Module 資料夾，或 `manifest.yaml` 用了工具不支援的 YAML 寫法（例如多行字串 `|`、anchor `&`）；訊息會指出行號。
- **目前裝的是測試版**：`skills-lock.json` 的 `ref` 是 `v5.6.0-beta.N`；正式版發布後執行第 2 步更新到 `v5.6.0` 即可。
- **需要回到 v5.5**：`update.sh --version v5.5.0`（或用 v5.5.0 tag 重新安裝）；v5.6 沒有改動專案資料。
