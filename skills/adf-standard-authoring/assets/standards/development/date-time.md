# 日期與年度格式（西元年）

## 目的
新系統的日期與年度一律使用西元年，避免民國年與西元年混用，造成查詢區間、排序、跨系統交換與報表錯誤。

## 規則
- **DEV-DATE-001-R1 畫面**：日期顯示與輸入使用 `yyyy/MM/dd`；日期時間使用 `yyyy/MM/dd HH:mm:ss`；年度欄位為 4 位數西元年（例如 `2024`）。
- **DEV-DATE-001-R2 API**：JSON 日期使用 `yyyy-MM-dd`；日期時間使用 ISO-8601，並明確約定時區。
- **DEV-DATE-001-R3 後端**：純日期使用 `LocalDate`，日期時間使用 `LocalDateTime` 或 `OffsetDateTime`；不得以字串保存、比較或排序日期。
- **DEV-DATE-001-R4 資料庫**：新欄位使用 `DATE`／`TIMESTAMP` 型別，不新增民國年字串欄位（例如 `CHAR(7)`）。若必須讀寫既有民國年欄位，轉換集中在 Repository／Mapper 層，業務邏輯只處理西元年。
- **DEV-DATE-001-R5 區間查詢**：起日包含當天 00:00:00；迄日包含整天，條件寫成 `< 迄日 + 1 天`，不可寫成 `<= 迄日 00:00:00`。
- **DEV-DATE-001-R6 輸入檢核**：輸入民國年（例如 `113/05/20`）或不存在的日期（例如 `2023/02/29`）時，顯示格式錯誤訊息，不自動猜測換算。

## 例外
對外公文、法定報表等業務明確要求顯示民國年時，只在該輸出層轉換，並在 Module 的 `spec/standards.md` 記錄例外與核准人。

## 驗證方式
- 迄日當天 23:59:59 建立的資料，用該迄日查詢可以查到。
- 閏年 `2024/02/29` 可輸入；`2023/02/29` 被拒絕。
- 輸入 `113/05/20` 顯示格式錯誤。
- API 回應日期格式為 `yyyy-MM-dd`。
