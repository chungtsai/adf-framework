# ADF v5.4 → v5.5 升級 SOP

## 適用範圍
已用 v5.1.0～v5.4.1 完成 `adf-project-install` 導入（有 `.adf/project.yaml` 與 `.adf/migration.json`）的專案。尚未導入的 v5.0 專案，請依 [v5.0 → v5.1 SOP](5.0-to-5.1.md) 的流程，並把文中的 tag 換成 v5.5.0。

v5.5 新增一支 Skill（`adf-acceptance-checklist`，共 34 支）與 manifest 的本次變更紀錄欄位。既有 Module 文件不需修改，也不撤銷任何核准狀態；不需要重跑 APPLY。

## 1. 升級前
1. 確認工作目錄乾淨，或先 commit 未提交變更。
2. 若曾手動修改已安裝的 ADF Skill，先把客製內容保存到專案外；重新安裝會覆蓋 Skill 檔案。

## 2. 更新

一行完成（自動沿用 Agent 與安裝模式、備份、比對、VERIFY，失敗自動還原；新 Skill 會一起安裝）：

```bash
curl -fsSL https://raw.githubusercontent.com/chungtsai/adf-framework/main/scripts/update.sh | bash -s -- --version v5.5.0
```

Windows PowerShell：`& ([scriptblock]::Create((irm https://raw.githubusercontent.com/chungtsai/adf-framework/main/scripts/update.ps1))) -Version v5.5.0`。

或手動執行（Agent 與安裝模式沿用原本的選擇）：

```bash
npx skills add https://github.com/chungtsai/adf-framework/tree/v5.5.0 --list
npx skills add https://github.com/chungtsai/adf-framework/tree/v5.5.0 --skill '*' -a claude-code
```

檢查 `skills-lock.json`：34 支 Skill（含 `adf-acceptance-checklist`）的 `ref` 都是 `v5.5.0`，`computedHash` 已更新。

## 3. 驗收

```bash
node <skill-root>/scripts/project.mjs CHECK <project>
node <skill-root>/scripts/project.mjs VERIFY <project>
node <skill-root>/scripts/project.mjs resolve <project> template/verification/acceptance.md
```

- CHECK 沒有 blockers，VERIFY 回傳 `verified`。
- 新範本能解析到專案內的 `adf-acceptance-checklist`。
- `.adf/project.yaml` 的 `tool_version` 維持 `5.1.0`～`5.4.1` 是正常的；5.5.0 接受此設定，不需要手動修改。

## 4. （可選）進行中的 Work Item 補上變更紀錄

重新啟動 Agent 載入新版 Skill 後，進行中的 Work Item 可以補上變更紀錄，讓驗收清單的範圍更準確（也在操作台網站「日常提示詞」）：

```text
modules/<module-id> 的 Work Item <work_item.id> 是 v5.5 之前建立的。請在 manifest 補上 work_item.base_ref（這個 Work Item 開始時的 commit：<commit>，不確定就問我）與 work_item.changes：比對 base_ref 到目前的 Module 文件差異，列出新增、修改、刪除的 REQ、BR、VAL、Q、UI、FS、TC，逐項讓我確認後再寫入；status.verification 加上 acceptance: pending。不要修改其他文件。
```

已完成的 Work Item 不需要補；之後的 CHANGE 由 `adf-feature-init` 自動填寫。

## 5. 驗收清單

Traceability 完成後：

```text
用 adf-acceptance-checklist 為 modules/<module-id> 目前的 Work Item 產生驗收清單。
```

Human 依清單操作並填寫「結果」與「簽核」後，再請 `adf-acceptance-checklist` 回收結果，通過後才執行 `adf-development-complete`。

## 常見問題
- **出現 `Missing/unsupported formal npx source`**：部分 Skill 仍是舊版或少了 `adf-acceptance-checklist`，重新執行第 2 步並安裝全部 34 支。
- **出現 `Installed skill differs from npx lock`**：已安裝的 Skill 被手動修改過，先把客製內容移到 `standards/` 或專案外，再重新安裝。
- **`adf-development-complete` 要求驗收清單**：v5.5 起結案前需要 Human 簽核的驗收清單；v5.5 之前建立的 Work Item 由 Human 決定是否補做。
- **目前裝的是測試版**：`skills-lock.json` 的 `ref` 是先前版本的 `-beta.N`；執行第 2 步更新到 `v5.5.0` 即可。
- **需要回到 v5.4**：`update.sh --version v5.4.1`（或用 v5.4.1 tag 重新安裝）；v5.5 沒有改動專案資料，已產生的驗收清單與 manifest 欄位保留。
