Loop Engineering 圖解

以範例網頁（ADF 操作台 docs/workbench/index.html）的 UI/UX 優化為例，說明每種 loop 適合的目的，以及 gap（每一輪之間的等待間隔）該怎麼抓。核心原則：先問在等什麼，再依那件事多快會變來決定間隔。

01 · 一輪 loop 的組成

每一輪都是：觀察 → 判斷 → 行動 → 等待

各種 loop 的觀察、判斷、行動都一樣，差別只在「等待」：由誰決定要等多久、下一輪要做什麼。判斷這一步要先檢查結束條件，條件成立就停止。

誰決定 gap 和下一輪要做什麼

不用 loop沒有要等的東西。同一輪連續做完，不需要 gap。
固定間隔由你決定 gap，每輪都一樣：/loop 30m …
自訂節奏由 Claude 每輪決定 gap，依等待的東西調整：/loop …
自主由 Claude 決定 gap，也決定要做什麼：/loop
排程工作依排程觸發，每次開新 session，最短每小時一次。
02 · 選型流程

依序問三個問題，就能決定 loop 類型

Q1

這件事需要等外部的東西嗎？

不需要（改→截圖→再改）同一輪做完，不用 loop
需要（部署、CI、別人的修改、時間）繼續問 Q2 →
Q2

每次都需要乾淨的新觀點嗎？

需要（例如每日稽核，避免沿用前一輪的結論）排程工作
不需要，延續同一段對話繼續問 Q3 →
Q3

等的東西多久會變？目標明確嗎？

變化速度穩定、可預期固定間隔
長短不一、做完一項才知道自訂節奏
沒有明確目標，要自己找問題自主
03 · 等比例時間軸 · 0–60 分鐘

六種情境在一小時內實際跑起來的樣子

色塊是 Claude 在工作，流動的虛線是 gap，數字是那段 gap 的分鐘數。時間線掃過色塊時，代表那個情境醒來工作。點一列可以看下方的詳細說明。

t = 0 分播放一小時（約 15 秒），看各情境何時醒來工作
時間軸只畫一小時。排程工作的下一次在 24 小時後，所以只畫出第一次。

05 · gap 對數尺

gap 要對準等待的東西，不是越短越好

自訂節奏的 gap 限制在 60–3600 秒之間。下方各段標出每種情境合理的 gap 範圍（對數刻度）。

規則 1

依等待的事物決定

部署約 3 分鐘，就約 180 秒檢查一次。每 60 秒查一次，大部分都是白跑。

規則 2

閒置用 20–30 分鐘

沒有特定要等的訊號時，用較長的 gap 維持推進，又不會一直打斷你。

規則 3

一定要寫結束條件

例如「清單完成就停止 loop」。沒有結束條件，loop 就會一直跑下去。

規則 4

沒變化只記一行

沒有變化的輪次只記「無變化」，避免一長串重複的報告淹沒真正的問題。
