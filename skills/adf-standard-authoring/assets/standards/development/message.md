# 共用訊息（新專案）

## 目的
新專案的使用者可見訊息統一由共用訊息目錄管理，讓相同情境顯示相同文字，並可集中修改與翻譯。

## 規則
- **DEV-MSG-001-R1 以代碼引用**：成功、錯誤、警告、確認、查無資料等訊息，一律由共用訊息目錄以訊息代碼取得；程式（前端與後端）不得硬寫訊息文字。
- **DEV-MSG-001-R2 一個語意一個代碼**：新增訊息前先查目錄；已有相同語意時沿用，不重複建立。代碼命名規則由專案定義並寫在訊息目錄開頭。
- **DEV-MSG-001-R3 參數化**：訊息中的變動內容使用參數，例如 `{0} 為必填`、`{0} 不可大於 {1}`；不以字串串接組合訊息。
- **DEV-MSG-001-R4 前後端分工**：後端 API 錯誤回傳訊息代碼與參數（配合 `DEV-ERR-001`）；前端依代碼顯示文字。
- **DEV-MSG-001-R5 不洩漏細節**：系統錯誤只顯示共用訊息與追蹤編號，不顯示 Stack Trace、SQL 或資料庫錯誤內容。

## 建議的共通訊息
| 情境 | 範例文字 |
|---|---|
| 查無資料 | 查無符合條件的資料 |
| 儲存成功 | 資料已儲存 |
| 刪除確認 | 確定要刪除此筆資料嗎？ |
| 必填 | {0} 為必填 |
| 格式錯誤 | {0} 格式不正確 |
| 無權限或不存在 | 查無資料或無權限存取 |
| 資料已被修改 | 資料已被其他使用者修改，請重新查詢 |
| 系統錯誤 | 系統發生錯誤，請洽系統管理員（追蹤編號：{0}） |

## 例外
移轉專案的訊息文字依 `MIG-DISP-001`，以舊系統為準。

## 驗證方式
- Code Review：前端與後端沒有硬寫的使用者訊息文字。
- 測試：錯誤情境顯示的文字與訊息目錄一致；系統錯誤畫面不出現 SQL 或 Stack Trace。
