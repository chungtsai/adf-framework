# 請求頻率限制

## 適用情境
登入、忘記密碼、寄送驗證碼或通知、查詢個資、匯出、呼叫外部付費服務，以及對外公開的 API。

## 規則
- **DEV-SEC-RATE-001-R1 依功能設定上限**：上述功能依使用者帳號、來源 IP 或兩者設定單位時間內的請求上限（例如登入每帳號每分鐘 5 次、寄送驗證碼每帳號每小時 5 次），上限集中設定並寫在設計文件。
- **DEV-SEC-RATE-001-R2 超過上限的回應**：回應 HTTP 429 與統一訊息（例如「操作過於頻繁，請稍後再試」），可附 `Retry-After`；不執行實際處理。
- **DEV-SEC-RATE-001-R3 高成本作業排隊**：大量匯出、報表產生等高成本作業限制同一使用者同時執行的數量，或改為非同步排隊（配合 `DEV-PAGE-001`）。
- **DEV-SEC-RATE-001-R4 記錄與告警**：超過上限的事件記錄稽核日誌（`DEV-SEC-AUDIT-001`）；短時間大量觸發時通知管理者。
- **DEV-SEC-RATE-001-R5 多台伺服器**：多台應用程式伺服器時，計數存放在共用儲存（例如 Redis）或由 Gateway／WAF 統一處理，避免每台各自計算。

## 驗證方式
- 對登入、寄送驗證碼 API 短時間連續呼叫超過上限：回應 429，且未實際寄出。
- 等待時間窗過後：可正常使用。
