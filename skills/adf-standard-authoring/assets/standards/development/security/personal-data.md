# 個人資料與敏感資料保護

## 目的
依個人資料保護法與組織資安規範，避免個資與敏感資料在畫面、匯出、日誌、儲存與傳輸中外洩，並能追查誰查閱了哪些資料。

## 用語
- **個資**：身分證字號、姓名、出生日期、電話、地址、Email、帳號、病歷、財務資料等可識別個人的資料。
- **敏感資料**：密碼、金鑰、Token、帳戶與卡號等外洩會造成損害的資料。

## 規則
- **DEV-SEC-PII-001-R1 盤點欄位**：設計時在 `design/design.md` 列出功能處理的個資與敏感欄位，以及各欄位的遮罩、加密與保存方式。
- **DEV-SEC-PII-001-R2 預設遮罩**：清單、明細、列印、匯出預設遮罩顯示，例如身分證字號 `A12****789`、電話 `0912***678`、姓名 `王○明`；遮罩規則由專案統一定義並在後端執行，不只在前端遮罩。
- **DEV-SEC-PII-001-R3 完整資料需權限**：顯示完整資料需另有功能權限（`DEV-SEC-001`），並記錄查閱紀錄（`DEV-SEC-AUDIT-001`）。
- **DEV-SEC-PII-001-R4 最小化**：只查詢、回傳、匯出功能需要的欄位；API 不回傳畫面用不到的個資。
- **DEV-SEC-PII-001-R5 儲存加密**：身分證字號、帳戶、卡號等高敏感欄位以資料庫或應用程式層加密儲存；需要查詢時使用雜湊欄位比對，不以明文建索引。
- **DEV-SEC-PII-001-R6 不進日誌與網址**：日誌、錯誤訊息、網址參數、前端 `localStorage` 不得出現完整個資與敏感資料。
- **DEV-SEC-PII-001-R7 匯出控管**：匯出個資需有權限、記錄匯出人與條件，並依 `DEV-PAGE-001` 限制筆數；必要時檔案加密或加浮水印。
- **DEV-SEC-PII-001-R8 測試資料**：開發與測試環境不得使用未去識別化的正式個資。

## 移轉專案
Legacy 未遮罩的畫面，Target 是否改為遮罩標 `REVIEW_REQUIRED`，由 Human 依法規決定，核准後列為 `APPROVED_BEHAVIOR_CHANGE`；不得因 `MIG-DISP-001` 保留明文外洩（依 `MIG-SEC-001`）。資料轉檔時加密欄位的轉換方式需經核准。

## 驗證方式
- 清單、明細、列印、匯出檔案中的個資依遮罩規則顯示；無「完整資料」權限者呼叫 API 也只取得遮罩值。
- 查閱完整資料與匯出個資後，稽核紀錄有對應資料。
- 檢查應用程式日誌與錯誤訊息沒有完整個資、密碼或 Token。
