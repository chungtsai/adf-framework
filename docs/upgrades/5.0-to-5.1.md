# ADF v5.0 → v5.1 移轉 SOP

## 適用範圍與版本
本版是「專案層級 npx skills、單一官方資源與安全移轉」，不包含舊提案的 Issue Tracking 或 .adf/framework 路徑重整。原來透過 npx、ZIP、clone 或手動複製者，最終都使用 npx skills 管理。Work Type 維持 NEW / CHANGE / MIGRATION。

本文件的正式來源為 v5.1.0 tag。tag 未發佈前，下列網址是發佈後的操作指令，不代表目前已存在，也不可用 main 取代正式來源宣稱移轉完成。安裝工具本身請在發佈驗收記錄可用的 skills npm 版本；本版不假設所有未來版本的 lockfile 都相容。

## 1. 安裝前盤點（還沒有安裝 Skill 也能執行）
1. 選定真正的專案根目錄；monorepo 每個採用 ADF 的範圍分別處理。
2. 查看專案 .agents/skills/、.claude/skills/，並盤點舊 .codex/skills/ 或其他 Agent 的手動目錄，以及全域同名 ADF Skill。記錄來源、版本、Agent 安裝模式與客製內容。
3. 保存 Git commit、未提交與未追蹤檔案。將舊 Skill、安裝工具 lockfile、CLAUDE.md、AGENTS.md、standards、modules、.adf 資料另備份到專案外；全域備份另存，不修改其他專案依賴。
4. 比較同名 Skill。確認客製內容已歸位且保存後，將手動同名副本移到 Agent 掃描範圍外。不要先覆寫再尋找客製內容。
5. 安裝前盤點採人工與檔案工具，不依賴尚未安裝的 adf-project-install。

## 2. 專案層級 npx 安裝
在專案根目錄執行；不要加 -g。先列出，再選明確 Agent，安裝所有 33 支 Skill，不能假設 update 自動取得新 Skill。

```bash
npx skills add https://github.com/chungtsai/adf-framework/tree/v5.1.0 --list
npx skills add https://github.com/chungtsai/adf-framework/tree/v5.1.0 --skill '*' -a claude-code
```

Codex 使用 `-a codex`。Windows 如需實體副本使用 `--copy`；重新安裝時也明確指定模式，不能假設一般 update 保留 copy 設定。使用互動確認，不用 --all 自動安裝到所有 Agent。

檢查 skills-lock.json：source=chungtsai/adf-framework、ref=v5.1.0、skillPath、computedHash。不可由人或 ADF 偽造 lockfile。工具版本或格式不相容時，先停止並驗證新版安裝工具。

## 3. 唯讀盤點與計畫
呼叫：

> 使用 adf-project-install，盤點本專案從 v5.0 導入 v5.1。先 CHECK 與 PLAN，列出來源、必要資訊歸位、衝突和備份，暫不寫入。

以實際安裝位置取代下列 `<skill-root>`；預設 canonical 位置為 `.agents/skills/adf-project-install`，copy 模式也可能位於 `.claude/skills/adf-project-install`。

```bash
node <skill-root>/scripts/project.mjs CHECK <project>
node <skill-root>/scripts/project.mjs PLAN <project> > <project外的plan.json>
```

計畫與 resolution 存於專案外，避免它們本身改變受保護資料。退出碼非零表示 blockers；輸出仍可供審查，但不能 APPLY。

## 4. 處理必要資訊歸位
| 舊資料 | 目的／處理 |
|---|---|
| framework/review | 官方來源歸到 adf-project-install/references；調整實際指引引用 |
| framework/templates | 官方範本歸到各 owner Skill assets；專案不保存副本 |
| .adf/templates 原版 | 雜湊辨識，備份後移除 |
| .adf/templates 客製或未知版 | 先人工確認必要資訊歸到 standards 或 modules 需求文件，再移除 |
| standards | 保留內容、ID、核准資訊，不覆寫、不強制採用官方範例 |
| modules | 保留規格、測試、結果、追溯、完成與核准紀錄 |
| 舊 Skill 客製內容 | 歸到專案指引或規範，停用舊同名 Skill；不保留客製範本 |
| CLAUDE.md / AGENTS.md | 人工調整必要引用，不整份覆寫 |

本工具不自動理解客製範本業務語意。對每個未知範本，建立外部 resolution JSON（SHA-256 可透過系統工具取得）：

```json
{
  "entries": [{
    "source": "module/spec/rules.md",
    "source_hash": "舊檔SHA256",
    "destination": "standards/development/project-rules.md",
    "destination_hash": "歸位後檔案SHA256",
    "human_confirmed": true
  }],
  "global_dispositions": []
}
```

有全域 ADF Skill 時，依 install-policy.md 記錄 Agent 使用專案來源的明確證據，不能直接刪除全域 Skill。歸位與指引修改是 Human 選定的前置變更，保存 diff；後續 APPLY 保護這個已確認基準。

```bash
node <skill-root>/scripts/project.mjs PLAN <project> <resolution.json> > <plan.json>
```

## 5. 套用選定計畫

```bash
node <skill-root>/scripts/project.mjs APPLY <project> <plan.json>
node <skill-root>/scripts/project.mjs VERIFY <project>
```

計畫過時、來源版本不同、存在未知 Skill、必要引用失效或未完成歸位時停止。APPLY 只新增缺少的 project.yaml、保存移轉紀錄、備份及移除已確認的 .adf/templates。不複製規範，不建立官方/客製範本，不重產 modules，不修改核准。

既有 project.yaml 為其他 YAML 格式時先保留並人工合併；工具只自動辨識 JSON-compatible YAML。舊專案記錄 document_schema=5.0、adopted_base=unknown，不宣稱內容已採用新版。停用規範不因缺檔而補回。

## 6. 完成驗收
- 專案 npx 來源與正式版本可確認，33 Skill 完整。
- Review、範本皆單一來源可解析；缺少 owner 不用替代副本，不跳過 Gate。
- 舊同名／未知 Skill 已處理，全域載入問題已確認。
- 必要資訊完成歸位，專案範本副本已清理。
- APPLY 前後 standards、modules、指引內容一致，完成及核准狀態保留。
- 重複導入沒有非預期寫入。
- Git diff 與備份位置可審查；VERIFY 通過才宣告完成。

缺少 Functional Scenario 或 specification 的已完成 Module，列為可選 CHANGE，不自動撤銷核准。發現行為衝突另走 CHANGE。

## 7. 回復

```bash
node <skill-root>/scripts/project.mjs RESTORE <project> <backup-id>
```

專案備份位於 .adf/backups/<id>，恢復旧範本和 project.yaml。若已有新的專案變更則拒絕自動回復，保留備份供人工處理。這個命令不還原 Skill；需另外用安裝前外部備份恢復 Skill、連結及原 lockfile，或從已記錄舊正式來源重新 npx 安裝。

## 日常更新
先使用目前的安裝 Skill CHECK，閱讀目標版 release notes 與相容性政策，再從選定正式 tag 安裝（每個版本有對應 checker）。`npx skills update` 是安裝工具的更新指令，不代表完成專案文件升級；不能跳過前置比較。新版工具與文件格式相容性另行驗證，v5.1.0 checker 不假裝支持未知未來版本。
