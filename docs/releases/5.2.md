# ADF v5.2

把重複在 32 支 Skill 裡的共用規範集中為單一來源，並開始以「操作契約」格式補強 Skill 的實際操作指引。Skill 名稱與數量（33 支）、Work Type、Gate 規則、Q&A schema 與 Module 文件格式都不變。

## 變更
- 新增共用資源（owner：`adf-project-install`）：
  - `core/invariants.md`：共通不變條件，統一 Compact Artifacts 清單（含 `functional-scenarios.md`、`specification.md`）與穩定 ID（含 `FS-*`、`TC-*`）。
  - `core/runtime-compat.md`：資源解析順序與舊專案相容性。
  - `core/skill-contract.md`：Skill 操作契約格式與固定「共用規範」引用區塊。
- 32 支 `SKILL.md` 移除「ADF 共通不變條件」、「Evidence-Guided Q&A」、「v5.1 資源與舊專案相容性」三段複製內容，改為固定引用區塊；33 支 SKILL.md 合計由 1,116 行降為 743 行（已含 `adf-backend-development` 新增的契約內容）。
- 修正 v5.1 的不一致：30 支 Skill 的 Compact Artifacts 清單缺少 `functional-scenarios.md` 與 `FS-*`。
- `adf-backend-development` 改寫為完整操作契約：輸入狀態表、步驟、輸出、完成條件、禁止事項與範例；description 加上何時使用與何時不用。
- `scripts/validate.js` 新增檢查：引用區塊須與契約完全一致、禁止重新加入已退役的共用段落、同一條規則出現在 3 支以上 Skill 即失敗、SKILL.md 引用的 resource key 必須存在。
- `project.mjs`：lockfile 的 ref 改由版本號推導（不再寫死 `v5.1.0`）；`resources.json` 新增 `compatible_tool_versions`，5.1.0 寫入的 `.adf/project.yaml` 可直接沿用。

[升級 SOP](../upgrades/5.1-to-5.2.md)。合併後須發佈 v5.2.0 tag 並實際驗收 npx 遠端安裝，才是可正式導入版本。

## 未包含
- 其餘 31 支 Skill 尚未改寫為完整操作契約，只完成共用區塊替換。
- Skill 收斂、manifest Stage 狀態值定義與 traceability 自動檢查屬後續版本。
- `docs/workbench` 頁面內容仍描述 v5.1.0，待另行更新。

## 驗證界線
`npm run validate` 與 `npm test`（22 項）驗證結構、共用區塊一致性、資源解析、升級相容與既有移轉行為。測試 fixture 模擬安裝後資料，不能代替 npx 實際下載驗收。
