# ADF v5.3 → v5.4 升級 SOP

## 適用範圍
已用 v5.1.0、v5.2.0 或 v5.3.0 完成 `adf-project-install` 導入（有 `.adf/project.yaml` 與 `.adf/migration.json`）的專案。尚未導入的 v5.0 專案，請依 [v5.0 → v5.1 SOP](5.0-to-5.1.md) 的流程，並把文中的 tag 換成 v5.4.0。

v5.4 不改既有 Module 文件格式，也不撤銷任何核准狀態。不需要重跑 APPLY。MIGRATION／RETROFIT_VERIFY Module 多了兩份文件（`analysis/legacy-behavior.md`、`verification/comparison.md`），既有 Module 需要時依第 4 步補填。

## 1. 升級前
0. （建議）先在測試專案或分支用測試版試跑：`curl -fsSL https://raw.githubusercontent.com/chungtsai/adf-framework/v5.4.0-beta.1/scripts/update.sh | bash -s -- --version v5.4.0-beta.1`；確認沒問題再更新正式專案。
1. 確認工作目錄乾淨，或先 commit 未提交變更。
2. 若曾手動修改已安裝的 ADF Skill，先把客製內容保存到專案外；重新安裝會覆蓋 Skill 檔案。

## 2. 更新

一行完成（自動沿用 Agent 與安裝模式、備份、比對、VERIFY，失敗自動還原）：

```bash
curl -fsSL https://raw.githubusercontent.com/chungtsai/adf-framework/main/scripts/update.sh | bash -s -- --version v5.4.0
```

Windows PowerShell：`& ([scriptblock]::Create((irm https://raw.githubusercontent.com/chungtsai/adf-framework/main/scripts/update.ps1))) -Version v5.4.0`。

或手動執行（Agent 與安裝模式沿用原本的選擇）：

```bash
npx skills add https://github.com/chungtsai/adf-framework/tree/v5.4.0 --list
npx skills add https://github.com/chungtsai/adf-framework/tree/v5.4.0 --skill '*' -a claude-code
```

檢查 `skills-lock.json`：33 支 Skill 的 `ref` 都是 `v5.4.0`，`computedHash` 已更新。

## 3. 驗收

```bash
node <skill-root>/scripts/project.mjs CHECK <project>
node <skill-root>/scripts/project.mjs VERIFY <project>
node <skill-root>/scripts/project.mjs resolve <project> template/analysis/legacy-behavior.md
node <skill-root>/scripts/project.mjs resolve <project> template/verification/comparison.md
```

- CHECK 沒有 blockers，VERIFY 回傳 `verified`。
- 兩個新範本都能解析到專案內的 Skill 目錄。
- `.adf/project.yaml` 的 `tool_version` 維持 `5.1.0`、`5.2.0` 或 `5.3.0` 是正常的；5.4.0 接受此設定，不需要手動修改。

## 4. （可選）既有移轉 Module 補填

只有 MIGRATION／RETROFIT_VERIFY Module 需要。重新啟動 Agent 載入新版 Skill 後，依序使用以下提示詞（也在操作台網站「日常提示詞 › 移轉與既有系統」）：

1. 找出要補填的 Module（唯讀）：

   ```text
   用 adf-ask 列出所有 Work Type 為 MIGRATION 或 RETROFIT_VERIFY 的 Module，逐一檢查是否已有 analysis/legacy-behavior.md 與 verification/comparison.md。用表格列出：Module、目前 Stage、缺少的文件、建議補填方式（進行中在目前 Work Item 補，已完成開 CHANGE 只補文件）。不要修改任何檔案。
   ```

2. 補填 Legacy 行為清單：

   ```text
   modules/<module-id> 是之前建立的 MIGRATION Module，還沒有 analysis/legacy-behavior.md。用 adf-legacy-analysis 依「既有 Module 補填」處理：<進行中，在目前 Work Item 補｜已完成，開 CHANGE 只補文件>。
   先把既有 Legacy Evidence、spec/rules.md、test-cases.md 已記錄的行為轉成 LB-*，沿用原證據位置，沒有位置的回 Legacy 原始碼 <路徑> 補上；再對每個入口補做 8 類盤點。新發現的行為標 REVIEW_REQUIRED，不要修改已核准的規則與程式。
   ```

3. 補填比對報告與涵蓋率：

   ```text
   modules/<module-id> 之前已做過新舊結果比對，雙邊 Raw Result 在 <路徑>。已有 analysis/legacy-behavior.md。用 adf-result-comparison 依「既有 Module 補填」處理：沿用既有 Raw Result、不重跑 Legacy，用比對腳本重新逐欄比對與分類，寫入 verification/comparison.md 並計算 LB-* 涵蓋率。與過去分類不同的差異標 REVIEW_REQUIRED，不要推翻已核准的決定，也不要修改 Target 程式。
   ```

補填不撤銷其他已核准的 Stage；新發現的行為沒有規則時回到 Rules Stage，已完成的 Module 經 Human 確認後另開 `CHANGE`。

## 常見問題
- **出現 `Missing/unsupported formal npx source`**：部分 Skill 仍是舊版，重新執行第 2 步並安裝全部 33 支。
- **出現 `Installed skill differs from npx lock`**：已安裝的 Skill 被手動修改過，先把客製內容移到 `standards/` 或專案外，再重新安裝。
- **resolve 新範本失敗**：`adf-legacy-analysis` 或 `adf-result-comparison` 仍是舊版，重新執行第 2 步。
- **目前裝的是測試版**：`skills-lock.json` 的 `ref` 是 `v5.4.0-beta.N`；正式版發布後執行第 2 步更新到 `v5.4.0`，腳本會顯示 `v5.4.0-beta.N → v5.4.0`。
- **需要回到 v5.3**：`update.sh --version v5.3.0`（或用 v5.3.0 tag 重新安裝）；v5.4 沒有改動專案資料，已補填的文件保留。
