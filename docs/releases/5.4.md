# ADF v5.4

## v5.4.1

涵蓋率定義明確化。只改 `adf-legacy-analysis` 與 `adf-result-comparison`；不需要重跑 APPLY，也不撤銷任何核准狀態。

- `adf-result-comparison` 步驟 5：以 `LB-*` 為單位計算三個指標，每個都寫出分子與分母：
  - 整體涵蓋率 = 已比對 `LB-*` ÷ `LB-*` 總數（另列 `UNKNOWN` 數量）。
  - 高風險涵蓋率 = 已比對的高風險 `LB-*` ÷ 高風險 `LB-*` 總數。
  - 通過率 = 通過的 `LB-*` ÷ 已比對 `LB-*`。
- 「已比對」：至少一個連到的 `TC-*` 有最終分類，且不是 `TEST_DATA_PROBLEM` 或 `REVIEW_REQUIRED`（含結果不穩定）。「通過」：已比對的 `TC-*` 全部為 `PASS` 或 `APPROVED_BEHAVIOR_CHANGE`。分母為 0 時寫「不適用」，不寫 100%。
- `comparison.md` 範本新增「涵蓋率」表；禁止事項加入「不得把 `TEST_DATA_PROBLEM`、`REVIEW_REQUIRED` 的案例算成已比對」。
- `adf-legacy-analysis` 步驟 4 與 `legacy-behavior.md` 範本新增 `風險` 欄：`HIGH`（交易、權限、副作用、金額或數量計算、使用者指定）或 `NORMAL`。
- 修正 macOS 內建 bash 3.2 執行 `install.sh`／`update.sh`／`standards.sh` 時出現 `PROJECT…: unbound variable`：緊接全形字的變數一律寫成 `${VAR}`，`npm run validate` 新增檢查。
- 修正 macOS 執行 `standards.sh` 時在「下載規範來源」後出現 `SyntaxError: Unexpected end of JSON input`：macOS 的暫存目錄經過 symlink（`/var` → `/private/var`），`project.mjs` 判斷是否直接執行時路徑不一致，結果不執行也沒有輸出。改以實際路徑比對，`npm test` 新增經 symlink 執行的測試。
- 既有系統導入的 manifest 寫法定案（`core/invariants.md`「Work Model」情境表）：`RETROFIT_VERIFY` 為 `type: MIGRATION`、`intents: [RETROFIT_VERIFY]`、`module.origin: MIGRATION`；`BASELINE_ADOPTION` 為 `type: NEW`、`intents: [BASELINE_ADOPTION]`、`module.origin: NEW`；兩者 `behavior.change_allowed: false`。manifest 範本末端改為中文示範；`adf-feature-init` 依表填寫、不確定有沒有 Legacy 時先詢問；`adf-retrofit-verification`、`adf-baseline-adoption` 新增「啟動條件」；`adf-legacy-analysis` 的 manifest 輸入條件改為看 `type`。既有 Module 不需修改，但建議依表補齊 `intents`。
- README 補充安裝後要 commit 進版控的檔案（Skill 目錄、`skills-lock.json`、`.adf/`），說明沒進版控時 `git worktree` 不會帶出這些檔案。
- 操作台網站同步；`compatible_tool_versions` 加入 5.4.1。
- 發布前先打 `v5.4.1-beta.1` 驗收，流程見 `docs/distribution.md`「測試版與正式發布」。由 v5.4.0 更新見[升級 SOP](../upgrades/5.3-to-5.4.md)第 5 步。

## v5.4.0

移轉品質強化：`adf-legacy-analysis` 與 `adf-result-comparison` 改寫為完整操作契約，降低「漏掉 Legacy 行為」與「錯的判成 PASS」兩種風險。Skill 名稱與數量（33 支）、Work Type、Gate 規則與 Q&A schema 都不變；不需要重跑 APPLY，也不撤銷任何核准狀態。

## 變更

### `adf-legacy-analysis`
- 依 `core/skill-contract.md` 補齊輸入、步驟、輸出、完成條件、禁止事項與範例。
- 每個入口追到最終 SQL 或副作用（JSP／JS → Filter → Servlet／Action → Service → DAO → SQL，含設定檔與共用 Util）。
- 8 類必查清單：輸入與驗證、分支、查詢、交易、副作用、錯誤處理、權限、隱含行為；每類標 `已檢查`／`不適用`／`無法取得`，不得留空。
- 行為以 `LB-*` 登錄，附 `檔案:行號` 與確定度（`CONFIRMED`／`UNKNOWN`）；註解與命名不算證據。
- 新增範本 `template/analysis/legacy-behavior.md`，產出 Module 的 `analysis/legacy-behavior.md`。

### `adf-result-comparison`
- 依 `core/skill-contract.md` 補齊輸入、步驟、輸出、完成條件、禁止事項與範例。
- 先做可比性檢查；差異由比對腳本（`verification/compare/`）逐欄找出，比對面向含畫面／API、DB 寫入、錯誤路徑與副作用。
- 7 種分類依固定順序判斷：`TEST_DATA_PROBLEM` → `PASS` → `APPROVED_BEHAVIOR_CHANGE` → `LEGACY_UNKNOWN` → `SPEC_GAP` → `MIGRATION_DEFECT` → `REVIEW_REQUIRED`。
- 以 `LB-*` 為分母回報涵蓋率並列出未涵蓋的行為；結果不穩定照實記錄，不得重跑到通過。
- 新增範本 `template/verification/comparison.md`，產出 Module 的 `verification/comparison.md`。

### 既有 Module 補填
- 兩支 Skill 新增「既有 Module 補填」：進行中的 Module 在目前 Work Item 補，已完成的開 `CHANGE` 只補文件；新發現的行為或與過去不同的分類標 `REVIEW_REQUIRED`，不推翻已核准的決定。
- 補填順序：先補 `analysis/legacy-behavior.md`，再補 `verification/comparison.md`。

### 測試版（beta）
- 正式 tag 前先打 `v5.4.0-beta.N`（或 `-rc.N`）在測試專案試裝、試跑，驗收後才發布正式版；流程見 `docs/distribution.md`「測試版與正式發布」。
- `install.sh`／`install.ps1`／`update.sh`／`update.ps1` 的 `--version`／`-Version` 接受 `vX.Y.Z`、`vX.Y.Z-beta.N`、`vX.Y.Z-rc.N`，其他格式在寫入前停止；測試版會在寫入前提示。
- 更新腳本以 `skills-lock.json` 的 `ref` 判斷目前版本，測試版可更新到同版號的正式版。
- `project.mjs` 接受同版號的測試版 `ref`，33 支 Skill 的 `ref` 必須一致；`VERIFY` 回傳 `ref` 與 `prerelease`。

### 共用規範與範本
- `core/invariants.md` 的 Compact Artifacts 新增 `analysis/legacy-behavior.md`（`LB-*`）與 `verification/comparison.md`；穩定識別碼加入 `LB-*`。
- `test-cases.md` 範本：MIGRATION／RETROFIT_VERIFY 的 `Source` 另連結 `LB-*`。

### 操作台網站
- 情境流程、QA 檢核、驗證方式、關鍵字（`LB-*`）、檢核點與文件說明同步。
- 「日常提示詞 › 移轉與既有系統」新增 3 個補填提示詞：找出要補填的 Module、補填 Legacy 行為清單、補填比對報告與涵蓋率。
- 修正提示詞範例中的 Migration Rule 編號為 `MIG-DATE-001`。

## 驗證界線
`npm run validate` 與 `npm test`（66 項）驗證結構、共用區塊一致性、資源解析、升級相容（含 5.3.0 寫入的設定）、一鍵安裝／更新（含測試版安裝、測試版到正式版更新、版號格式檢查）與規範安裝。CI 中 `.ps1` 只有靜態檢查；`v5.4.0-beta.1` 已以 npx 遠端安裝、更新與 Windows PowerShell（`install.ps1`／`update.ps1`）實際驗收通過。兩支 Skill 的實際效果（涵蓋率與分類順序）尚未在真實移轉專案試行。

v5.4.1：`npm run validate`（新增 `.sh` 變數寫法檢查）與 `npm test`（68 項，含經 symlink 執行 `standards.sh`）通過；`v5.4.1-beta.1` 已發布供驗收。macOS bash 3.2 的修正依錯誤訊息與 bash 3.2 已知行為處理，CI 為 Linux bash 5，未在 CI 重現。`standards.sh` 的 JSON 解析錯誤已在 Linux 以 symlink 路徑重現並確認修正，未在 macOS 實機驗證。
