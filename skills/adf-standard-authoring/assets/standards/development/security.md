# 功能權限（無權限必須限制存取）

## 目的
使用者沒有某功能的權限時，無論從選單、直接輸入網址、書籤或直接呼叫 API，都不能使用該功能。以後端授權為準；畫面隱藏不是授權。

## 規則
- **DEV-SEC-001-R1 後端為準**：每個頁面、API 與下載端點在執行前，由後端依登入身分（Session／Token）檢查功能權限；檢查失敗不執行任何查詢或異動。
- **DEV-SEC-001-R2 預設拒絕**：新增的頁面、API 一律預設需要權限；未在權限設定中登錄的功能視同無權限。允許匿名存取的端點需逐一列在白名單並經 Human 核准。
- **DEV-SEC-001-R3 動作分開檢查**：查詢、新增、修改、刪除、匯出、列印、核准等動作各自檢查權限；有查詢權限不代表可以異動或匯出。
- **DEV-SEC-001-R4 不只靠畫面**：隱藏選單、按鈕或停用欄位只是使用者體驗，不是保護；直接輸入網址或呼叫 API 仍必須被後端擋下。
- **DEV-SEC-001-R5 集中實作**：權限檢查使用共用機制（Filter、Interceptor、Annotation、Middleware 等），不在各功能中各自撰寫，避免遺漏。
- **DEV-SEC-001-R6 回應一致**：無權限時回應統一的錯誤（例如 HTTP 403 與「無權限執行此功能」），不透露功能內部資訊；並記錄稽核日誌（使用者、功能、時間、來源 IP）。
- **DEV-SEC-001-R7 權限即時生效**：權限被取消後，下一次請求即須拒絕；不得只在登入時檢查一次並長期快取於前端。

## 與其他規範的關係
- 功能權限（能不能用這個功能）由本規範處理；資料範圍（能看到哪些資料）依 `DEV-SEC-SCOPE-001`。兩者都要通過。

## 驗證方式
每個功能至少一組權限測試：
1. 有權限的使用者：可正常使用。
2. 沒有權限的使用者直接輸入頁面網址：顯示無權限，不顯示資料。
3. 沒有權限的使用者直接呼叫查詢、異動、匯出 API：回應無權限，資料庫沒有任何異動，稽核日誌有紀錄。
4. 只有查詢權限的使用者呼叫修改、刪除 API：回應無權限。
