# 參數 Token（防止竄改與限制資料範圍）

## 目的
前端必須回傳給後端的關鍵參數（檔案參考、資料鍵值、多步驟流程的前一步結果），以後端簽發的 Token 保護，防止使用者竄改參數或跳過步驟，並把後續作業限制在前一步核准的資料範圍內。

## 適用情境
- **欄位 Token**：檔案代碼、資料 ID 等需由前端帶回的參數（配合 `DEV-SEC-PATH-001`）。
- **流程 Token**：API 有順序性時（例如 查詢 → 確認 → 送出、上傳 → 檢核 → 匯入、驗證身分 → 變更資料），前一步的結果作為後一步的依據。

## 規則
- **DEV-SEC-TOKEN-001-R1 後端簽發**：Token 只由後端產生，內容為伺服器端保存的隨機值（存於 Session、快取或資料表），或以 HMAC 等伺服器金鑰簽章；不得只用 Base64、可預測的流水號或前端產生的值。
- **DEV-SEC-TOKEN-001-R2 綁定範圍**：Token 綁定使用者（Session）、用途（功能代碼、步驟）、允許的資料範圍（例如 ID 清單、查詢條件），並設有效期限。
- **DEV-SEC-TOKEN-001-R3 以 Token 為準**：後續步驟只接受 Token，由 Token 還原前一步的結果與資料範圍；前端另外傳入的 ID 或條件若與 Token 範圍不符，一律拒絕，不得以前端值為準。
- **DEV-SEC-TOKEN-001-R4 順序檢查**：流程 Token 記錄目前步驟；未完成前一步、跳步或重複執行同一步時拒絕。
- **DEV-SEC-TOKEN-001-R5 一次性**：會造成異動的步驟（送出、匯入、刪除）使用後即作廢，防止重送；唯讀用途（例如下載）可在有效期限內重複使用。
- **DEV-SEC-TOKEN-001-R6 驗證失敗**：Token 不存在、過期、簽章不符、使用者或用途不符時，回應統一錯誤（例如「作業已逾時或資料已變更，請重新操作」），不執行任何查詢或異動，並記錄稽核日誌。
- **DEV-SEC-TOKEN-001-R7 不取代權限**：Token 驗證通過後仍須檢查功能權限與資料範圍（`DEV-SEC-001`、`DEV-SEC-SCOPE-001`）。
- **DEV-SEC-TOKEN-001-R8 不放敏感資料**：Token 不包含密碼、個資等明文；需要攜帶資料時只放識別值並簽章，或只存在伺服器端。

## 範例
```text
1. POST /import/check    上傳並檢核 → 後端保存檢核結果，回傳 checkToken（綁定使用者、功能、檢核通過的資料列）
2. POST /import/apply    只帶 checkToken → 後端由 Token 取出檢核通過的資料匯入，Token 作廢
   ✗ 不接受前端在第 2 步重新傳入資料內容或另外加入的 ID
```

## 驗證方式
- 竄改 Token 任一字元、使用過期 Token、使用其他使用者的 Token：回應統一錯誤，資料無異動。
- 跳過前一步直接呼叫後一步 API、重送已完成的異動步驟：被拒絕。
- 在後一步額外傳入 Token 範圍以外的 ID：被拒絕或忽略，只處理 Token 範圍內的資料。
