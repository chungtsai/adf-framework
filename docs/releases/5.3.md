# ADF v5.3

一鍵安裝與更新、專案起始規範（安全性為主）與一鍵規範安裝。Skill 名稱與數量（33 支）、Work Type、Gate 規則、Q&A schema 與 Module 文件格式都不變；不需要重跑 APPLY，也不撤銷任何核准狀態。

## 變更

### 一鍵安裝與更新
- `scripts/install.sh`／`install.ps1`：全新專案一行指令完成 npx 安裝 → 逐檔比對 → PLAN → APPLY → VERIFY；偵測到已安裝時轉交更新，有舊版痕跡則在寫入前停止。
- `scripts/update.sh`／`update.ps1`：一行指令更新（更新前 VERIFY → 相容性檢查 → 專案外備份 → npx 重裝 → 逐檔比對 → VERIFY，失敗自動還原）。
- 寫入前都會詢問 `[y/N]`，`--yes`／`-Yes`／`ADF_YES=1` 略過。
- 修正：`curl | bash` 時 npx 讀取 stdin 導致安裝中斷；Windows PowerShell 5.1 誤判 Node.js 版本。

### 專案起始規範
- 官方規範範例改寫為繁體中文、frontmatter（`id`、`version`、`status: DRAFT`、`change_policy`）、規則編號、範例、移轉專案說明與驗證方式。
- 共 27 項，分為兩類：
  - **建議項目（18 項）**：SQL Injection（含必填 `LIKE` 不可只輸入 `%`）、資料範圍、功能權限、分頁與筆數上限、修改刪除強制條件、檔案路徑、參數 Token、舊系統弱點不得移轉（`MIG-SEC-001`）、XSS、CSRF、登入與 Session、參數綁定白名單、後端輸入驗證、個資、上傳與匯出、機密管理、稽核日誌、第三方元件。
  - **選填項目（9 項）**：民國年 → 西元年、移轉顯示一致、共用訊息、導向網址與 SSRF、XXE 與反序列化、指令注入、HTTP 安全標頭、重複送出與同時修改、頻率限制。
- `scripts/standards.sh`／`standards.ps1`：建議項目預設全部安裝、輸入編號排除；選填項目輸入編號加入。非互動用 `--recommended --exclude <編號> --add <編號>`，或 `--select` 只裝指定項目。只新增檔案，同路徑或同 ID 一律略過。
- `project.mjs STANDARDS`：新增 `--recommended`、`--exclude`、`--add`、`--select`、`--dry-run`；可用編號、pack ID 或規範 ID 指定。
- `adf-standard-authoring` 新增「後續加入官方規範」：之後要加入的規範，在 Agent 中以提示詞要求，dry-run 確認後以 DRAFT 寫入。

### 操作台網站
- 新增「一鍵安裝與更新」、「專案規範安裝」（分組勾選並產生指令）與日常提示詞範例。

[升級 SOP](../upgrades/5.2-to-5.3.md)。合併後須發佈 v5.3.0 tag 並實際驗收 npx 遠端安裝，才是可正式導入版本。

## 相容性
- `resources.json` 的 `compatible_tool_versions` 為 5.1.0、5.2.0、5.3.0；舊版寫入的 `.adf/project.yaml` 可直接沿用。
- 起始規範只寫入專案 `standards/`，更新 ADF 不會修改已安裝的規範。

## 驗證界線
`npm run validate` 與 `npm test`（56 項）驗證結構、共用區塊一致性、資源解析、升級相容、一鍵安裝／更新（以假的 npx 離線執行）與規範安裝。`.ps1` 只有靜態檢查；測試 fixture 不能代替 npx 實際下載與 Windows 實機驗收。
