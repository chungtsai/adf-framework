# ADF v5.6 → v5.7 升級 SOP

## 適用範圍
已用 v5.1.0～v5.6.0 完成 `adf-project-install` 導入（有 `.adf/project.yaml` 與 `.adf/migration.json`）的專案。

v5.7.0 將 `module-check.mjs` 與 `core/module-format.md` 正式納入強制流程，Skill 數量（34 支）、Work Type、Intent 與 manifest 範本不變；既有已完成 Module **不會**被撤銷核准，不需要重跑 APPLY。

## 1. 升級前
1. 確認工作目錄乾淨，或先 commit 未提交變更。
2. 若曾手動修改已安裝的 ADF Skill，先把客製內容保存到專案外。

## 2. 更新

一行完成（自動沿用 Agent 與安裝模式、備份、比對、VERIFY，失敗自動還原）：

```bash
curl -fsSL https://raw.githubusercontent.com/chungtsai/adf-framework/main/scripts/update.sh | bash -s -- --version v5.7.0
```

Windows PowerShell：`& ([scriptblock]::Create((irm https://raw.githubusercontent.com/chungtsai/adf-framework/main/scripts/update.ps1))) -Version v5.7.0`。

## 3. 驗收

```bash
node <skill-root>/scripts/project.mjs CHECK <project>
node <skill-root>/scripts/project.mjs VERIFY <project>
node <skill-root>/scripts/module-check.mjs <project>/modules/<module-id> --gate
```

- CHECK 沒有 blockers，VERIFY 回傳 `verified`。
- `.adf/project.yaml` 的 `tool_version` 維持 `5.1.0`～`5.6.0` 是正常的，不需要手動修改。

## 4. 既有文件未達標準時的調整策略

升版後，**進行中（Active）的 Work Item** 在進入 `adf-development-complete` 前將強制執行 `module-check.mjs --gate`。若出現 `BLOCKED`，依問題性質分三類處理：

### A 類：純格式／寫法問題（`L-01～L-03`、`L-06`、`L-13`、`L-14`、`M-01`、殘留範本範例列）
- 內容與行為皆未改變時，直接修正排版、補齊標題列或刪除殘留範例列（如 `TC-001`、`FS-001`）。
- 依 `core/invariants.md`，純格式修正**不登記**至 `work_item.changes`，也不撤銷已核准狀態。
- 升版前已開啟的 Active Work Item 若純格式債務過大，可由 Human 明確記錄「有條件通過」至 `blockers` 並排入後續 `CHANGE`。

### B 類：追溯／紀錄未對齊（`L-10`、`R-02`、`R-04`、`R-05`、`R-08`、`M-06`、`M-07`）
- 依可查證證據（`comparison.md`、CI 測試報告、ALM Run、Human 簽核紀錄）補齊對齊並填寫 `Evidence` 欄。
- **嚴禁**在拆列 `L-10`（一列多 Test）時將舊列單一 Result 直接複製給每個 TC；查無明確執行紀錄者一律填 `NOT_RUN`。
- `R-05`（`changes` 與 `base_ref` 差異不一致）維持 `REVIEW_REQUIRED` 交 Human 確認，不可由工具自動修改。

### C 類：實質缺漏／合規風險（`L-08`、`L-09`、`R-01`、`R-03`、`R-06`、`R-09`、`G-02`/`G-05`/`G-06`/`G-11`）
- **一律強制阻擋，不可豁免**。須退回對應 Skill 補齊測試、移除 Secret、修正非 `SELECT` 的 Verification SQL 或完成 Q&A，重走對應 Human Gate。
- **嚴禁**刪列洗綠報告（刪除須保留該列並改 `Status: REMOVED`）或弱化 Expected Result。

### 已完成歷史 Module（碰到才轉換）
- 不需一次修改全專案既有 Module；平常維持原狀，下次開 `CHANGE` 修改到該檔時再由對應 Skill 順手正規化。
- 若需納入 CI 統一健檢，可另開 **Documentation Retrofit CHANGE**（`behavior.change_allowed: false`），專職調整格式與 `traceability.md` 拆列，不更動程式碼，經 Traceability Human Gate 確認完成。
