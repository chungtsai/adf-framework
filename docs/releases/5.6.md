# ADF v5.6

## v5.6.0

新增 Module 檢查工具 `module-check.mjs`（試用功能）：用程式檢查 Module 文件的格式、ID 連結與覆蓋率，並提供結案預檢。Skill 數量（34 支）、Work Type、Intent、manifest 範本與 Q&A schema 都不變；不需要重跑 APPLY，也不撤銷任何核准狀態。

本版只發布工具，**Skill 的流程沒有改**：各 Skill 不會自動執行它，使用者可自行決定要不要在 Gate 前執行。格式規則目前是草案（repo 的 `docs/proposals/module-format.md`），收集真實專案的回饋後，再決定是否把規則登錄為共用規範、放進 Skill 步驟。

## 變更

### 新工具：`adf-project-install/scripts/module-check.mjs`

```bash
node <skill-root>/scripts/module-check.mjs modules/<module-id>            # 檢查與覆蓋率
node <skill-root>/scripts/module-check.mjs modules/<module-id> --gate     # 另做結案預檢
node <skill-root>/scripts/module-check.mjs modules/<module-id> --json     # JSON 輸出（CI 用）
```

`<skill-root>` 是專案內的 `adf-project-install` 目錄，例如 `.claude/skills/adf-project-install`。只讀檔案，不修改任何 Artifact，也不連網；不需要 `npm install`（Node 18 以上）。

- **格式（L-*）**：
  - 表格欄數、必要欄位、ID 寫法與重複、狀態值、Rule 前綴與章節、範圍寫法。
  - traceability 一列寫多個 Test 的舊寫法，以警告提示。
  - Verification SQL 只能用 `SELECT`；Cleanup SQL 要註明人工確認後執行。
  - 疑似 Secret：明確的金鑰格式為錯誤，`password=` 等關鍵字為警告；訊息不輸出內容。
- **manifest（M-*）**：
  - 欄位完整性：直接比對 `adf-feature-init` 的 manifest 範本。
  - `CHANGE_ME`、Work Type、Intent 與狀態值。
  - `RETROFIT_VERIFY`、`BASELINE_ADOPTION` 的欄位組合。
  - 問題數與核准狀態是否矛盾。
  - `base_ref` 建立後不得改寫。建立時為 `null`、導入 git 後補一次是允許的。
- **連結（R-*）**：
  - 引用的 ID 不存在。
  - TC 的 Scenario 與 FS 的 Related Test 不一致。
  - 沒有測試驗證的 REQ 或 Rule。
  - `work_item.changes` 與 Artifact 不一致，以及與 `base_ref` 起的實際差異不一致：只回報 `REVIEW_REQUIRED`，不自動修正；只改 Status 不算修改。
  - 適用的規範不存在或尚未核准。
  - 規格書引用不存在的 ID。
  - 有效項目引用了已刪除（`REMOVED`）的 ID。
- **覆蓋率**：
  - 項目：Requirement、Rule、Functional Scenario、本次變更、Legacy 行為（整體、高風險、通過率）、驗收與執行結果。
  - 只計算已核准（`APPROVED`、`VERIFIED`）的測試；只有未核准測試的項目另外列出。
  - 分母為 0 時寫「不適用」；百分比無條件捨去。
- **結案預檢（`--gate`）**：
  - 依 `adf-development-complete` 的各 Gate 整理 12 項（G-01～G-12），結論為 `READY`、`HUMAN_REQUIRED` 或 `BLOCKED`。
  - 報告固定註明「工具的結論不等於核准」，結案仍須 Human 確認。
- **exit code**：
  - 一般檢查：`0` 沒有錯誤、`1` 有錯誤、`2` 工具無法執行。
  - `--gate`：`0` READY、`1` BLOCKED、`3` HUMAN_REQUIRED。

### 修正：支援新版 npx skills 的 `skills-lock.json`
- 此修正已於 v5.5.1 先行發布，v5.6.0（`v5.6.0-beta.2` 起）同步包含。
- npx skills 1.9 起寫入 `skills-lock.json` version 2：每支 Skill 多了 `commit` 欄位，`computedHash` 的算法也改變（排除 `metadata.json` 與 `.git`／`__pycache__`／`__pypackages__`、CRLF 正規化、路徑以位元組排序）。npx 讀到 version 1 時會自動遷移成 version 2。
- v5.5.0 以前的 `project.mjs` 只接受 version 1：用新版 npx 全新安裝時 PLAN 出現 `Unsupported npx skills lock format`；更新時重裝後 VERIFY 失敗並自動還原。
- `project.mjs` 改為同時支援 version 1 與 2，各自依 npx 的算法驗證 `computedHash`；其他版本仍然阻擋。version 2 的算法以 npx skills 1.9.1 實際計算的結果驗證（`tests/migration.test.mjs`）。
- 這個問題在 `v5.6.0-beta.1` 驗收時發現，已於 v5.5.1 先行發布修正，並於 `v5.6.0-beta.2` 起納入 v5.6。

### 已知限制
- 檢查依草案的格式規則。範本中的範例列（`TC-001`、`FS-001`、`LB-001` 等）若還留在 Module 文件裡，會被當成真資料，可能報出「引用的 ID 不存在」；請刪除範例列或改成實際內容。
- `spec/requirements.md`、`spec/rules.md`、`spec/standards.md` 的範本目前沒有表格。工具接受的寫法：
  - 需求：表格欄位 `ID｜名稱｜Status`，或標題寫法 `## REQ-001 標題` 加 `Status:` 行。
  - 規則：在 `## Business Rules` 等章節放 `ID｜規則｜預期行為｜Source｜Status` 表格。
  - 規範適用性：表格欄位 `Standard｜適用｜理由`。
- 版控差異比對需要 git，且 `base_ref` 指向的 commit 必須存在（shallow clone 可能找不到）。

## 相容性
- `resources.json` 的 `compatible_tool_versions` 加入 5.6.0（5.1.0～5.5.1 寫入的 `.adf/project.yaml` 可直接沿用）。
- Module 文件、manifest 與核准狀態都不需要修改。
- `skills-lock.json` 必須有 34 支 Skill 且 `ref` 一致。

## 驗證界線
`npm run validate`（34 支 Skill）與 `npm test` 通過；`module-check.mjs` 由 `tests/module-check.test.mjs` 以測試資料涵蓋，版控比對的測試會實際建立 git repo。`v5.6.0-beta.1` 驗收時發現新版 npx skills 的 lock version 2 無法安裝，於 `v5.6.0-beta.2` 修正；工具尚未在真實專案的 Module 試跑，誤報情況待回饋。
