# 民國年轉西元年（Legacy → Target）

## 目的
舊系統使用民國年、新系統使用西元年（`DEV-DATE-001`）。本規則核准「表示方式」的轉換，讓結果比對時不把年份格式不同誤判為缺陷，同時確保日期語意（同一天、同一年度）不變。

## 核准的轉換
- 換算：西元年 = 民國年 + 1911。例如 `113/05/20`、`1130520` ↔ `2024-05-20`；`113` 年度 ↔ `2024` 年度。
- Legacy 常見格式：`yyy/MM/dd`、`yyyMMdd`（7 位字串）、`yy/MM/dd`（民國 100 年前，例如 `99/01/01` = `2010-01-01`）、前導零 `099`。
- 只轉換表示方式；以下必須與 Legacy 相同，除非另有核准：
  - 日期查詢命中的資料筆數與內容（區間是否包含起迄日）。
  - 依日期排序的結果順序。
  - 空日期的判斷（依 `MIG-NULL-001`）。
  - 年度歸屬（例如會計年度、跨年度資料的歸屬）。

## Normalization（結果比對時）
- 比對前，將 Module `spec/rules.md` 列為日期或年度的欄位，由 Legacy 民國年轉為西元年標準格式 `yyyy-MM-dd`（年度為 `yyyy`）後再比較。
- 未列在規則中的欄位不轉換；轉換後仍不同即為差異，依 `adf-result-comparison` 分類。

## 需要人工判斷（標 REVIEW_REQUIRED）
- Legacy 資料中的特殊值，例如 `0000000`、`9999999`、`000/00/00` 代表「無」或「永久有效」。
- 民國前或 2 位數年份可能有歧義的資料。
- 無法換算的非法日期（例如 `112/02/30`）。

## 驗證方式
- Golden Case 至少包含：一般日期、民國 100 年前（2 位數年份）、閏年 2/29、跨年度區間查詢、空日期、Legacy 特殊值。
- 舊資料的實際轉換（Data Migration）屬另一項工作，需另訂轉換腳本與數量核對。
